# 星燈港：HD-2D 回合制冒險

黃昏的港口小鎮，燈塔的星燈熄了。旅人和花店的米菈、旅行商人賽恩一起，從被影獸佔據的小鎮出發，穿過霧之森，登上星之古塔，奪回被「熄星者」帶走的星之心。

全篇分為三章加終章，共 16 種遭遇、兩場頭目戰。依平衡模擬，主線戰鬥合計約 60 回合，加上探索與劇情，推估一輪約 30 分鐘（尚未有真人計時，實際長短視操作與練功而定）。

## 怎麼玩
1. 用瀏覽器打開 `index.html`（需經由網站或本機伺服器開啟，直接雙擊檔案會因瀏覽器安全限制無法載入模組）。
2. 按「開始冒險」。有存檔時標題會出現「繼續冒險」，「新的冒險」要按兩次才會清掉舊進度。
3. 左上角的目標欄會提示下一步要去哪裡。

| 章節 | 地點 | 內容 |
| --- | --- | --- |
| 第一章 熄燈的港口 | 小鎮 | 打倒守著碎片的影獸，找回三顆星之碎片。米菈在這一章加入 |
| 第二章 霧之森 | 北門外的森林 | 燈塔亮起後北門開啟，賽恩加入。森林盡頭的橋上有頭目「霧狼王」 |
| 第三章 星之古塔 | 森林北方的遺跡 | 霧散去後才能進入。祭壇上的「熄星者」是最終頭目 |
| 終章 星燈再臨 | 燈塔 | 星之心回到燈芯，之後可以繼續在鎮上漫步 |

| 動作 | 電腦 | 手機 |
| --- | --- | --- |
| 移動 | WASD 或方向鍵 | 在畫面左半邊按住拖曳（虛擬搖桿） |
| 對話、調查、下一句 | 空白鍵、Enter、E | 右下「調查」或點對話框 |
| 戰鬥選單 | ↑↓ 選擇、←→ 蓄力、空白鍵決定、Esc 返回 | 點選單；選目標時點敵人頭上的名牌；選單左上的「返回」回上一層 |

本機試玩：在 repo 根目錄執行 `npx http-server -p 8080`，開啟 `http://127.0.0.1:8080/hd2d/`。

## 戰鬥規則
- **行動順序**：每回合依速度排序，畫面上方顯示本回合與下回合的順序。頭目一回合行動兩次。
- **護盾與弱點**：每個敵人頭上有護盾數字。用牠的弱點（劍、匕、杖、火、風、光）攻擊，每打中一下削減 1 點；連擊技一次能削好幾點。打中過的弱點會記住，下次遇到同種敵人直接顯示。賽恩的「鑑定」可以一次看穿全部弱點。
- **破防**：護盾歸零時敵人破防，跳過本回合剩下的行動和下一回合，期間受到的傷害變成 1.5 倍。
- **BP 蓄力**：每人每回合累積 1 點 BP（最多 5 點），一次最多用 3 點。普通攻擊每多 1 點多打一下；技能與回復則提高威力。蓄力的那一回合不會累積 BP。
- **防禦**：受到的傷害減半，下回合優先行動。
- **道具**：回復藥草（HP）、星露（SP）、星之羽（讓倒下的同伴復活）。寶箱、守衛和部分影獸會掉落。
- **成長**：勝利後全員獲得經驗值，升級時會學到新技能，最高 20 級。後加入的同伴從目前的隊伍等級開始。
- **全滅**：可以完全回復後再試一次；一般遭遇也可以選擇撤退。頭目戰與守衛戰不能逃跑。

## 地圖上的影獸與休息點
- 地圖上看得見的影獸就是遭遇，碰到才會戰鬥。會遊蕩的影獸在玩家靠近時會追過來；守衛和頭目不會移動。
- 休息點：鎮上的水井、森林營火、古塔前的星之石像。休息會讓全員完全回復並存檔，但附近被打倒的遊蕩影獸會重新出現。
- 進度會在接任務、同伴加入、拾取碎片、開寶箱、戰鬥勝利後與休息時自動存檔，只存在這台裝置的瀏覽器裡（`localStorage` 的 `hd2d-save`）。

## HD-2D 畫面怎麼做出來
- **像素角色放在 3D 場景裡**：角色、怪物、樹木、灌木都是即時繪製的 16 像素／公尺像素圖，貼在略向後傾的平面上，會受燈光照亮並投下影子。
- **立體透視模型般的地形**：每格 1 公尺，鄰格較低時補上側面，形成高台、海岸斷面、棧橋與遺跡。
- **區域氣氛**：小鎮、霧之森、星之古塔各有自己的霧色、天光與日光，鏡頭移動時平滑過渡。
- **遮擋淡出**：角色走到樹後或建築後時，擋住角色的部分會以網點淡出。
- **戰鬥場景**：獨立的 3D 舞台（小鎮、海邊、森林、遺跡、頭目祭壇），沿用同一套後製，受擊閃光、破防與技能特效都是即時運算。
- **後製**：移軸景深、光暈、暗角、冷暗部與暖亮部的色調，最後才做色調映射與 sRGB 轉換，見 `post.js`。

所有像素圖都由程式在載入時繪製（`pixel.js`、`monsters.js`），沒有使用外部圖檔，也沒有仿製任何既有遊戲的角色或素材。Three.js 0.186.1 隨專案保存在 `vendor/`（MIT 授權），不依賴執行時 CDN。

## 聲音
- 配樂與音效全部由 `audio.js` 用 Web Audio 即時合成，沒有外部音檔，旋律都是為這個遊戲寫的原創曲。
- 六首配樂：標題（也用在終章與結局後的小鎮）、小鎮、霧之森、星之古塔、一般戰鬥、頭目戰。依角色所在位置自動切換，換曲時會交叉淡入淡出；點燈演出時配樂暫停，讓位給點燈的音效。
- 音效涵蓋選單游標、確定與取消、對話打字、遭遇、各屬性的命中、弱點、破防、回復、倒下、頭目第二階段、勝利、全滅、升級、同伴加入、寶箱、碎片、休息與章節標題。
- 選單的「聲音」可以選「音樂與音效」「只有音效」「關閉」，選擇存在這台裝置的瀏覽器裡（`localStorage` 的 `hd2d-sound`）。
- 瀏覽器規定網頁要等玩家第一次按鍵或點擊後才能發聲，所以標題畫面一開始是安靜的。切到別的分頁時聲音會暫停。
- iPhone 開著靜音開關時，網頁的 Web Audio 可能不會出聲（未在實機驗證）。

## 畫質
- **精緻**：景深、光暈、陰影，像素比上限 1.5。
- **流暢**：關閉後製與陰影，像素比 1。
- 遊玩中若連續兩個 3 秒區間平均低於 28 FPS，會自動改用流暢畫質並提示。手動在選單選過畫質後，就不再自動切換；選擇只存在這台裝置的瀏覽器裡。
- 無法使用 WebGL 時顯示說明，不會停在空白畫面。

## 調整數值
```
node tools/平衡模擬.mjs 300
```
用 `battle-core.js` 的自動戰鬥，依主線順序（含同伴加入、休息點）連續打完所有戰鬥，重複 300 次，列出每場的勝率、平均回合數、剩餘血量與等級。修改 `data.js` 的數值後先跑這支，再進遊戲確認手感。自動戰鬥比真人保守，模擬的勝率可以當作難度的下限參考。

## 自動檢查
```
NODE_PATH=$(npm root -g) node tools/檢查.cjs <截圖輸出資料夾>
```
腳本會自己啟動靜態伺服器，用 Chromium（SwiftShader 軟體繪圖）從標題一路玩到結局：行走與碰撞、接任務、兩位同伴加入、第一場戰鬥的手動蓄力與攻擊、三場守衛戰與碎片、點亮燈塔、存檔後重新讀取、霧之森與營地休息、霧狼王、星之古塔與石像、熄星者第二階段、結局、暫停選單的畫質與聲音切換、各場景的配樂是否換對，以及手機直向的虛擬搖桿、觸控戰鬥與「返回」鈕、手機橫向的暫停選單與戰鬥版面，最後檢查沒有頁面錯誤。結果寫在輸出資料夾的 `結果.json`。軟體繪圖很慢，整輪約需 10～20 分鐘。

測試會用 `window.__hd2d` 的測試介面瞬間移動、開啟自動戰鬥、加快戰鬥演出，並在頭目戰前直接調高等級。這支腳本只證明流程走得通，難度交給平衡模擬。

## 給未來 session 的信
1. 自動檢查證明的是「能玩、流程能走完、沒有錯誤」，不能證明好不好看或手機實機流暢。SwiftShader 下的幀率沒有參考價值。
2. 新增 NPC、影獸、寶箱或休息點時，要同步 `main.js` 的 `talks`、`SYMBOLS`、`CHESTS`、`REST`，以及 `world.js` 地圖上的阻擋格；放錯格子最常見的後果是走不到或卡進牆裡。
3. 新增敵人時：`data.js` 寫數值與遭遇、`monsters.js` 畫圖、主線用到的話加進 `tools/平衡模擬.mjs` 的路線，再跑一次模擬。
4. 新增會發光的物件時，記得點光源有成本。流暢畫質沒有後製，HDR 亮色會被直接壓成白色，兩種畫質都要看過。
5. 改配樂時照 `audio.js` 裡 `TRACKS` 上方的記譜說明寫，每小節的格數要剛好等於 `bar`，旋律小節數要是和弦數的倍數。音量是用離線算圖量過峰值與響度後調的，自動檢查只確認換曲正確，聽起來好不好要用耳朵判斷。
