# 自然漫遊 v2 場景美化紀錄（2026-10-02）

基準版本：commit `bb6bfa6`（含同日〈優化紀錄〉的四項修正）。需求：「盡可能的美化 nature-v2 場景」。

## 前提與範圍

- [假設] 「場景」指四個可行走的 3D 景色（森林、海岸、秋林、雪林）的畫面；首頁版面與文案不動，介面只調整漫步模式的暗角。
- [假設] 不新增任何外部下載素材，避免授權落檔與下載量增加。新視覺全部由程式產生：以既有 Poly Haven CC0 葉片／針葉圖集當「筆刷」在畫布上合成，其餘交給著色器。
- 必須保持不變：行走、碰撞、邊界與地面高度演算法（`驗證.cjs` 以原始碼片段抽取 `pathX`…`terrainHeight` 與 `allowed`／`move` 執行，兩段文字逐位元組未改）、`createExplorer` 對外介面、畫質分級與自動降級、原版靜態備援。

## 美化前的問題（同視角截圖診斷）

1. 世界是一塊 134 公尺見方的平地，地平線露出地板盡頭；走到邊緣只看得到空曠平面與天空。
2. 天空是同一張 HDR，四景共用，霧色與地平線不一致。
3. 樹冠由「一張卡片一片葉」組成（每棵 728 張），直桿樹枝穿出樹冠，像棒棒糖；秋葉是大片紙片感的褐色橢圓。
4. 溪流是一條淺綠色平板；海面像規律條紋的塑膠，泡沫是等距白線。
5. 岩石是深色圓團；草叢稀疏且偏暗；地面單一色調、步道是硬邊色帶。
6. 漫步模式底部的綠黑漸層在雪地上像一條髒污。

## 改了什麼

| 類別 | 內容 | 主要位置 |
|---|---|---|
| 大氣 | 霧改為「距離＋高度衰減」的指數霧，朝太陽方向帶入暖色散射；遠山的山腳比山頂更朦朧 | `shaders.js` 開頭的霧著色片段 |
| 天空 | 程序化天空：漸層、太陽光暈與日輪、雲層；地平線收斂到霧色，與遠景無縫銜接 | `shaders.js` `skyMaterial` |
| 環境光 | 以同一片天空烘出 PMREM 環境光，地面、岩石的反光與天色一致；不再載入 `sky.hdr` | `engine.js` `sky()` |
| 四景光線 | 森林：清晨斜光；海岸：低角度夕照；秋林：午後暖金逆光；雪林：薄日柔光。太陽方向、天色、霧、曝光集中在 `LOOKS` 表 | `engine.js` `LOOKS` |
| 遠景 | 沿可行走地形邊界的同一組頂點向外放射的環帶（約 3.2 公里），起伏丘陵、遠山與雪線；海岸有岬角與小島。接縫頂點完全相同、法線以同一高度函式計算 | `engine.js` `landscapeHeight`、`terrain()` |
| 林帶 | 世界邊界外 900 棵交叉卡片樹（雪林為積雪松樹剪影、海岸為低矮灌叢），銜接遠山林相 | `engine.js` `farForest()` |
| 闊葉樹 | 一張卡片即一整簇葉（約 260 片小葉合成），樹冠由 4–7 個葉團組成；樹冠球面法線＋內暗外亮＋逆光透葉；樹幹收在樹冠內、根部外擴並長苔 | `foliage.js` `drawLeafCluster`、`engine.js` `forestTrees()` |
| 秋色 | 金黃與火紅兩種樹冠貼圖輪替；地面貼合地形的落葉薄片、飄落翻轉的秋葉 | `foliage.js`、`engine.js` `leafLitter()` |
| 松樹 | 層層下垂的松枝卡片＋獨立積雪層；視線高度的低枝避開步道 | `foliage.js` `drawPineBranch`／`drawPineSnow` |
| 地被 | 由下而上漸亮的草叢、步道兩側較茂密的成片分佈、野花、林下與溪岸蕨類；海岸沙丘草 | `foliage.js` `drawGrass`／`drawFern`、`engine.js` `undergrowth()` |
| 地表 | 去重複的大尺度色彩變化、軟邊步道、溪岸濕土、苔蘚斑塊、樹腳與岩腳遮蔽（AO）、濕沙、遠山林相與雪線、雪地閃光 | `shaders.js` `patchGround` |
| 岩石 | 雜訊塑形後以隨機平面切出岩面、平底半埋，三種外形；頂面依場景長苔、覆雪或沾沙 | `engine.js` `boulderGeometry()`、`shaders.js` `patchRock` |
| 溪水 | 嵌入溪床的較寬水面，依水深半透明，反射天空與兩岸樹影，順流細紋與閃點 | `shaders.js` `creekMaterial` |

## 成本與驗證

以下數據來自本容器：無顯示卡，Chromium 以 SwiftShader 軟體模擬 WebGL2，視窗 1280×720。

| 項目 | 美化前 | 美化後 |
|---|---|---|
| 首次載入下載量（`resource` 項目 encodedBodySize 加總，同〈優化紀錄〉算法） | 19.64 MB | 17.24 MB |
| 每格三角形（細緻畫質、起點視角，含陰影圖） | 森林 1,430,582／秋林 1,429,458／雪林 1,010,700／海岸 502,694 | 森林 1,223,454／秋林 1,222,458／雪林 880,352／海岸 599,584 |
| 每格三角形（流暢畫質、起點視角） | 森林 417,365／秋林 419,761／雪林 620,988／海岸 83,784 | 森林 415,029／秋林 412,749／雪林 450,272／海岸 131,166 |
| 繪製呼叫（細緻畫質、起點） | 森林 27／秋林 28／雪林 14／海岸 18 | 森林 37／秋林 39／雪林 20／海岸 25 |
| 軟體渲染單格秒數（非起點視角平均，含陰影圖更新） | 森林 5.3／秋林 5.1／雪林 6.3／海岸 0.97 | 森林 5.8／秋林 5.7／雪林 6.3／海岸 1.8 |
| 切景 CPU 建構（貼圖合成、地形、植被；不含首次著色器編譯） | — | 每景約 0.3–0.5 秒 |
| 重複切景兩輪後 WebGL texture／buffer／program 數 | — | 29／141／24，第二輪未增加；細緻↔流暢切換亦未累積 |
| 未處理的 JavaScript 錯誤 | — | 0（四景、兩種畫質、390px 手機寬度） |

- [事實] 葉叢改為整簇卡片後，近景樹冠卡片數約為舊版的四分之一（細緻畫質舊版每棵 728 張單葉卡，新版 180 張葉叢卡）；省下的預算用在遠景、光束與地被。森林、秋林、雪林的每格三角形仍比舊版少；海岸因海面網格延伸到地平線而增加。
- [推論] 軟體渲染的秒數只能粗略反映填充率與頂點成本；實際顯示卡的瓶頸分佈不同。海岸相對變重（巨大的半透明海面逐像素計算浪與天空反射），但仍是四景中最輕的一景。
- [事實] 開發中曾發現畫布合成在 GPU 加速的 2D canvas 上逐筆回讀，切景要 7–9 秒；改為 CPU 畫布（`willReadFrequently`）後降到上表數字。

## 沒有動的部分

- `pathX`、`creekX`、`shoreline`、`terrainHeight`、`allowed`、`move` 的原始碼文字；碰撞半徑規則、世界邊界、步行速度與相機高度。
- `createExplorer` 的參數與回傳方法、`window.__natureV2` 觀測介面、`app.js`、`adaptive.js`、`index.html`、`classic/`。
- `assets/` 內所有檔案逐位元組不變。`sky.hdr`、`leaf-normal.jpg`、`twig-normal.jpg` 仍保留供來源查核，但執行時不再載入。

## 限制與風險

- [事實] 本次所有畫面都是軟體渲染截圖，沒有在實體顯示卡或手機上量測 FPS。
- [推論] 最可能失敗的情境是低階手機：逐像素的霧、地表雜訊與葉叢重疊繪製會增加片段負擔。既有的自動降級（細緻 → 流暢 → 原版靜態）仍會接手，但「多快被降級」需要實機確認。
- [推論] 首次進入的著色器編譯時間比舊版長（地表、海面著色器較複雜），在慢裝置上載入畫面會停留較久。
- [假設] 美感與寫實度是主觀判斷；截圖對照只能證明「畫面確實改變且無錯誤」，不能證明真人覺得更美。建議由主人或其他真人實機看過再定版。
- `驗證.cjs` 仍以 Codex 工作區的 `dist/` 路徑為前提，在這份扁平化副本無法直接重跑（既有限制）；本次以同等方法另行檢查資源累積、畫質切換與錯誤。

## 重跑方式

在上層資料夾啟動靜態伺服器（埠 4174）後：

- 四景固定視角截圖：`node tools/場景截圖.cjs <輸出資料夾>`。無顯示卡時加 `NATURE_SOFTWARE=1`，截流暢畫質加 `NATURE_QUALITY=balanced`；Playwright 位置可用 `PLAYWRIGHT_PATH` 指定。
- 既有快速檢查：`node tools/快速檢查.cjs <截圖輸出資料夾>`。
